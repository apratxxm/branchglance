# macOS port inventory

This is an inventory and proposed migration plan, not a claim of macOS support. The current widget and packaging path are Windows-first. Shared Python reducers, API logic and vanilla JavaScript can remain common where their contracts are platform-neutral.

## Storage and provider paths

The cross-platform data code still contains Windows-specific default paths. `token_tracker/product.py:212-214`, `token_tracker/product.py:460-504` chooses LocalAppData/AppData and product state; `token_tracker/codex_client.py:42-46` has Windows Codex executable candidates; `token_tracker/claude_provider.py:52-57` already derives Claude Code's home from `Path.home()` or `CLAUDE_HOME`. Implement a single platform path provider before changing these call sites. Keep provider-owned data read-only except for explicitly consented Claude hook settings and Branchglance's own event/state files.

## Suggested order

1. Freeze the shared platform contracts for paths, process identity/liveness, instance locking, windows, shell integration and packaging. Add platform adapters without moving provider policy or reducers into OS-specific modules.
2. Make provider CLI discovery and Claude hook command generation platform-aware. Preserve consent, owned-settings edits, event schema and test isolation.
3. Port storage roots and atomic file operations; add macOS path, permission, symlink and upgrade-migration tests.
4. Implement the Cocoa window adapter: screen selection, backing scale, notch/safe-area layout, levels, drag, resize, tray/status item, secondary settings window and shortcut permissions.
5. Build the `.app`, optional LaunchAgent/Login Item integration, installer/update/rollback and uninstall ownership. Add codesign and notarization to release automation.
6. Run pure Python and Node checks on every platform; run Windows adapter tests on Windows and Cocoa/window/signing acceptance on macOS. Do not present mocked tests as native acceptance.
